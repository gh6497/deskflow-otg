# Android 伴侣应用与桌面 GUI

`android/deskflow-otg` 是可选的手机端伴侣应用。0.1.1 同时监听系统 USB 连接状态及 accessory 拔出广播，
通过已授权的通知监听服务调用活动媒体会话的 `pause()`。不是新的键鼠连接方式，也不替代
USB AOA / BLE、scrcpy 音频或剪贴板；不安装它仍可使用原有功能。

0.1.3 按用户要求移除等待，USB 已连接转为断开后在广播回调内立即请求暂停，
不保留定时器或待执行动作；首次 sticky 状态不触发暂停，已知 USB 断开状态保持去重。
没有 USB 状态广播的 ROM 保留 accessory 事件回退，但无法据此精确判断重连或区分重复事件。
监听服务失联/销毁时重置状态基线。
适用于所有 USB 数据连接，不仅限于 Deskflow；USB 插线本身不会恢复播放。

0.1.2 对断开时可见的所有活动媒体会话逐个检查，播放/缓冲中的都发送 `pause()`，
不再只暂停优先级最高的一个。单会话状态读取或暂停异常不会中断后续会话；
暂停、停止、空状态的会话不处理。日志记录各播放器请求及失败并汇总请求数，
不能把请求数当作播放器已确认暂停数。没有向系统暴露媒体会话的播放器无法通过此 API 控制。

## Deskflow 实际连接状态（0.1.4）

同时更新桌面 GUI 和 APK，安装后在手机上打开一次。首页显示「正在连接 / 已连接 /
正在断开 / 已断开 / 状态未知」，中英文跟随系统；无需通知使用权即可查看状态。
只有桥接进程发出完整握手后的 `connected` 事件，GUI 才上报已连接；USB 插线不算连接。

桌面 GUI 通过现有已授权 ADB 显式广播同步，活动会话每 5 秒续报。手机前台每秒刷新，
以手机 `elapsedRealtime` 和启动次数校验，15 秒无新报告或手机重启后显示未知。
已断开只尝试上报一次，同样在 15 秒后过期，避免把旧会话状态误当成当前状态。
ADB 不在线、APK 未安装、被强制停止或 ROM 拦截广播时，不阻塞键鼠，也不自动打开应用。
拔线时 ADB 可能已不可用，不能保证即时收到断开；租约过期后不再显示已连接。

每条命令先以 `adb -s TARGET get-state` 核对在线，再向固定
`com.github.gh6497.deskflowotg/.ConnectionStatusReceiver` 发送固定协议和状态值（0.1.4 为 v1，0.1.5 为 v2）。
接收器要求发送者的 `android.permission.DUMP`（ADB shell 持有），不向普通应用开放伪造状态，
不请求该特权、不授予通知使用权。单条命令最多 2 秒，一条同步管线在途；更新合并为最新状态，
旧在线检查不能上报旧连接。没有安装/打开/修改权限或自动 pair/connect/disconnect/kill-server。

设备 ADB 目标非空时优先使用（含已连接的无线 ADB），否则仅 USB 使用该设备的 USB 序列号。
BLE 必须配置显式 ADB 目标，不能以 BLE MAC 代替。Windows USB 驱动互斥时可使用已连接的
无线 ADB；Linux / Windows / macOS 共用 Qt 实现，无新增平台专用依赖。CLI 暂不提供状态同步。
无 ADB 时手机显示未知，原有无需调试的 AOA HID 及拔线立即暂停逻辑保持不变。

## 连接后自动恢复播放器（0.1.5）

同时更新桌面 GUI 和 APK（版本码 6）。手机首页新增「连接后自动恢复所选播放器」，
**默认关闭**。先打开音乐播放器播放一次，在伴侣应用中点击「从活动媒体会话选择播放器」，
选定应用后开启开关；可先手动暂停音乐，再连接 Deskflow 验证。选择、开启开关本身不触发播放。
列表只来自通知使用权允许访问的活动媒体会话，不扫描全部已安装应用。

- 只有真实 Deskflow 握手成功才允许播放，不以 USB 插线、ADB 在线或鼠标切入手机为触发。
  首版仅支持指定播放器；无可用会话时跳过，不启动播放器，不回退其他应用。
- 通过已有通知使用权调用目标会话的 `TransportControls.play()`，只对 `STATE_PAUSED`
  且声明 `ACTION_PLAY` 的会话尝试一次。播放/缓冲、停止、空状态、不支持播放均跳过；
  不使用播放/暂停切换键，不同时恢复所有播放器。请求成功不代表播放器确认播放。
- 需要实际绑定中的通知监听服务；服务未运行、授权撤销、播放器失效或异常时跳过，
  不启动服务、不静默授权、不在稍后重试。原有拔线立即暂停所有播放/缓冲会话保持不变。
- 桌面状态协议 v2 增加 `connection_id`（每次真实连接独立 UUID）、`playback_ready`
  和仅一次的 `play_event`。5 秒心跳只续租，不携带新的播放请求；ADB 离线时消耗该请求，
  恢复在线后不补播。单管线合并仍丢弃旧检查回调，排队的播放事件超过 4 秒即丢弃。
- 手机处理播放事件前同步持久化最近 64 个已消耗连接 ID（含关闭开关、服务缺失或播放失败），
  同一连接的重复事件不会重试。App 重启、监听重绑、租约过期续报不补播；
  自动播放后用户手动暂停，不会被心跳恢复。真正断开再连接会生成新 ID，允许再次尝试。
- 开启音频转发时，Linux/Windows 只有在收到有效 scrcpy RAW 音频头、且 ALSA/WASAPI
  输出设备成功初始化后才上报 `audio-ready`，不等待首帧 PCM、不固定延迟几秒。
  握手与音频就绪两者皆满足才发送播放事件；音频初始化失败不播放，等待期间断开会取消。
  这表示链路就绪，并非已经听到声音；手机 ROM、播放器音频捕获策略仍需真机验证。
- macOS 继续支持无音频转发的连接后播放，未新增 macOS 音频后端。
  BLE 只有配置显式、已在线的 ADB 目标才可接收事件；CLI 与无 ADB 的连接仍不支持此功能。

新版 APK 仍接受 v1 状态，但不会因此播放；v2 桌面需要新版 APK（旧 APK 不识别 v2）。
测试使用纯 Java 策略、fake ADB/桥接及 ALSA null 输出，不接触手机、USB、系统蓝牙或真实扬声器；
不能等同通知服务保活、ROM 广播投递、播放器恢复或 Windows/macOS 真机验收。
`android_connection_receiver` 另用最小 Android API fake 执行真实接收器/设置类，验证默认关闭、
先持久化再分发、重复事件、模拟重绑/重启、旧协议、写盘失败及64条历史淘汰；不验证真实服务绑定。

## GUI 使用

在「设备配置」中选择 USB 连接，找到「Android 伴侣应用（可选）」：

1. 手机需 Android 10+。先开启并授权 USB 调试，或自行配对、连接无线 ADB。
   「共享服务」里的 ADB 程序必须可用。
2. 核对设备页的「ADB 目标」：非空时优先使用它（支持 `host:port` / `[IPv6]:port`），
   留空才使用当前设备的 USB 序列号。每条操作都使用 `adb -s`，不会自动选择其他手机，
   不自动 pair/connect、不回退 USB、不 disconnect/kill-server。
3. 选择**已签名**的伴侣 APK，或使用桌面包附带的 APK。点击「安装 / 更新 APK」。
   使用 `install -r --user current` 保留应用数据；签名不匹配、降级或手机拒绝安装时报告错误，
   **不会先卸载旧应用**，不使用 `-d`、`-g`。
4. 点击「打开手机端设置」，启动固定包 `com.github.gh6497.deskflowotg` 的 `MainActivity`。
   在手机内点击通知使用权按钮，手动开启 deskflow-otg。桌面端不静默授予权限。
5. 点击「检查授权状态」，查询当前 Android 用户的安装和通知使用权设置。
   不读取通知正文，不记录其他应用的通知授权列表。
6. 按下节完成手机的自启动和电池策略设置，确认监听服务运行后，再测试拔线暂停。

安装、打开、查询均为用户主动操作，不在 GUI 启动、键鼠连接或 USB 自动连接时执行。
当前设备需先断开键鼠会话；操作期间锁定设备选择及连接入口。退出等待有界 ADB 操作完成，
安装最长 60 秒，其他单条命令最长 10 秒。安装结果、授权提示中英双语实时切换，错误详情见设备日志。
APK 路径全局保存，设备 ADB 目标仍按设备保存。BLE 页不提供此 USB 拔出功能入口。

Windows 的 ADB 与 WinUSB 可能不能同时访问同一 USB 接口；可先用 ADB 安装授权，
或填写已连接的无线 ADB 目标，再使用原有 AOA HID 连接。不更换驱动、不重新连接设备。

## 手机端生效条件与后台限制

**安装成功、通知使用权已开启，不等于拔线暂停一定生效。** USB 事件由清单中的
`UsbDisconnectReceiver` 接收，不依赖 `DeskflowNotificationListenerService` 当时已经绑定；通知使用权
仍是读取和控制媒体会话的必要授权。应用被强制停止或 ROM 完全禁止后台运行时，仍可能收不到广播。

请在手机上针对 **deskflow-otg** 检查以下设置：

1. **通知使用权**：在系统的通知使用权设置中手动启用；这是访问媒体会话的授权，
   不是普通的「允许发送通知」开关。
2. **自启动 / 后台自启动**：如果 ROM 提供此设置，允许应用自启动及后台启动。
   小米 / Redmi 的 MIUI、HyperOS 等系统可能阻止 Android 自动绑定通知监听服务。
3. **电池策略**：将应用省电策略设为「无限制」「不限制」或同等选项；如有「允许后台活动」
   开关，也需允许。不同品牌、系统版本的菜单路径和名称不同，没有独立自启动开关的系统
   不需要寻找或额外安装权限工具。
4. **安装、更新后打开一次应用**：更新 APK 会结束旧应用进程，ROM 不一定恢复服务绑定。
   打开应用后仍无效时，在手机上关闭再开启本应用的通知使用权，然后重新测试。
   应用被强制停止、被后台管理清理或手机重启后，也需重新确认服务是否已恢复。

这些设置必须由用户在手机上操作，桌面 GUI 和 APK 不会静默修改自启动、电池策略或通知授权。
GUI「检查授权状态」只查询通知使用权，**不检查自启动、电池策略、Receiver 是否被 ROM 拦截或播放器响应**。
放宽后台限制也不能保证所有 ROM 都会投递广播；进程被强制停止时，错过的拔线事件不会在之后补处理。

排查时可使用已授权的 ADB，只读检查指定手机（将 `SERIAL` 替换为实际目标）：

```bash
adb -s SERIAL shell dumpsys activity services com.github.gh6497.deskflowotg
adb -s SERIAL logcat -d -v threadtime -s deskflow-otg:V '*:S'
```

如果需要检查媒体访问能力，服务列表应能看到 `DeskflowNotificationListenerService` 的服务记录与绑定信息；
日志中的 `media pause listener connected` 表示曾成功绑定，但 USB Receiver 不再依赖这条绑定。
若系统日志显示应用被强制停止、后台广播被拦截，或通知使用权已撤销，应先处理对应设置，
而不是反复调整暂停延迟。

Redmi K20 Pro / Android 14 已观察到：覆盖安装 0.1.3 后通知授权仍保留，但系统报告
`AutStart Unable to bind notification listener service`，服务列表为空；此时系统虽发出
USB 断开广播，应用也收不到。该现象与播放器是否响应 `pause()` 是不同的问题。
恢复服务后，请重新连接 USB，再在媒体播放时拔线验证；USB 插线本身不自动恢复播放。

## 桌面打包

桌面 GUI 不强制依赖 Android SDK。发布者先构建并签名 APK，再显式提供：

```bash
cmake -S . -B build-gui -DBUILD_GUI=ON \
  -DCOMPANION_APK=/absolute/path/deskflow-otg-signed.apk \
  -DCMAKE_PREFIX_PATH=/path/to/Qt/6.8.3/gcc_64
cmake --build build-gui --parallel
cmake --install build-gui --prefix "$PWD/stage"
```

CMake 将文件复制到 GUI 可执行文件旁，统一命名 `deskflow-otg-companion.apk`，
并安装到 Linux/Windows `bin/` 或 macOS `.app/Contents/MacOS/`，沿用现有桌面包收集流程。
CMake 只检查文件路径及后缀，不验证 Android 签名；签名有效性由发布者检查、手机安装器验证。
不传 `COMPANION_APK` 的普通桌面构建/CI 不附带 APK，GUI 仍允许手动选择；
不自动打包工作目录的 debug 或 unsigned APK，不引入签名私钥。

## 验证边界

`gui_logic` / `gui_window` 使用 fake ADB 覆盖目标固定、无线目标优先、USB 序列号回退、
安装更新与失败、缺包、打开错误、精确授权组件匹配、重复操作、语言切换、设置保存及退出等待。
`android_usb_disconnect` 另外用真实 Java 状态机覆盖首次 sticky 状态、HID-only 断开、
重复及乱序广播、立即断开处理、快速重新枚举也暂停、连续多次插拔与服务重绑定。
同一测试还覆盖多播放器暂停策略，包括多个播放/缓冲会话、空列表、跳过暂停会话及异常后继续。
状态策略额外覆盖固定状态校验、15 秒过期边界、续报及重启失效；`companion_status` 用
fake ADB/桥接验证握手事件才显示连接、续报、正常断开、无线目标优先、无目标不回退、
离线不阻塞 HID、旧检查回调丢弃及命令超时。未访问手机，广播权限与 ROM 后台投递仍需真机验收。
需要 JDK；没有 JDK 时显式跳过。以上测试不访问 USB、系统蓝牙或真实手机。

授权设置包含组件名**不等于** Android 已绑定通知监听服务，也不代表拔出暂停已验证。
当前 AOA HID 主路径不执行 accessory-mode 切换，因此不能只依赖 `USB_ACCESSORY_DETACHED`。
Redmi K20 Pro / Android 14 已确认发出 `USB_STATE`，旧版 0.1.0 没有进入暂停逻辑；
新版仍需安装后实测，其他 ROM 的平台广播投递与播放器响应不作保证，不支持 BLE 断开暂停。
USB 重新枚举和快速拔插的短暂断开也会暂停；USB 重连不会撤销暂停请求，只有显式开启的真实
Deskflow 连接自动播放功能可能随后请求恢复所选播放器。
立即处理表示不增加人为等待，仍受系统广播投递与播放器响应耗时影响。
原有音频断开时的 ADB `media_session dispatch pause` 路径保持不变。

## 鼠标中键 Home / 右键 Back（当前桌面：无需伴侣应用）

根据用户确认的安卓系统快捷键，桌面「中键功能」选择「返回安卓桌面（Win+Enter）」、
「右键功能」选择「安卓返回键（Win+Backspace）」后，直接通过已有 HID 键盘发送系统组合键。
Win 对应 HID Left GUI / Android Meta；不是普通键盘 Home，也不是由伴侣 App 拦截。
**不需要安装/更新 APK、开启无障碍服务、通知使用权或 ADB。** 两项仍独立按设备保存，默认普通鼠标按钮。
USB、Linux BLE、Windows BLE 共用核心，macOS 支持 USB；不改变描述符、BLE注册或IPC参数值。

首次鼠标按下发送 Meta-down、组合键-down、组合键-up、Meta-up 四条报告，鼠标松开与重复按下
不额外触发，长按不会让后续输入一直带 Win，也不会因 Enter/Backspace 自动重复而连续返回。
组合报告保留真实按键和修饰键，不修改真实键盘状态；若目标 Enter/Backspace 已按住或6键位满，
跳过本次导航并记录警告，不强制松开重按真实按键。额外真实修饰键也会保留，ROM是否仍识别
组合取决于系统；建议无其他键按住时测试。切出、重置、键盘屏障取消和关闭清除鼠标去重标记。

`bridge_transport` 覆盖绝对/相对模式、四条报告顺序、真实键/修饰键保留、按住鼠标时继续打字、
双按钮独立、重复去重、满键/目标键已按住跳过、中途发送失败仍尝试释放及退出清理。
GUI回归检查双语选项、设备隔离、自动连接和设置恢复。离线通过不等于手机系统动作验收；
用户须在支持上述快捷键的 ROM 上实测。无需停用或卸载已有伴侣应用，其其他功能不受影响。

2026-11-05 用户确认本次系统快捷键版本使用正常。该确认仅限本次用户测试，不代表所有 ROM、
macOS/Windows 或 BLE 路径均已完成真机验收。

### 历史实现：F13/F14 + 伴侣无障碍服务

以下保留旧版桌面与 APK 兼容说明；当前桌面的 Home/Back 已不使用该路径。

桌面 GUI 的「中键功能」选择「返回安卓桌面（需要伴侣应用）」后，桥接程序不会发送普通
鼠标中键，而是通过已注册的 HID 键盘发送保留的 F13 按键。伴侣应用中的
`DeskflowAccessibilityService` 请求过滤 F13，在按下时调用
`AccessibilityService.performGlobalAction(GLOBAL_ACTION_HOME)`，返回安卓桌面并消费该按键。

使用前在手机伴侣应用首页点击「打开无障碍设置」，启用「Deskflow OTG 返回桌面 / 返回上一级」服务；
桌面 GUI 的该选项默认关闭，普通中键行为不变。该路径不依赖 ADB，但需要用户手动授予无障碍
权限；部分 ROM 的后台限制可能停止无障碍服务。若服务未启用，Home 模式下的中键会被桥接端
转换为 F13，但不会执行安卓 Home，也不会发送普通中键。

### 鼠标右键映射安卓 Back（0.1.7）

同时更新桌面 GUI 和手机 APK（版本码 9），在桌面「右键功能」选择「安卓返回键（需要伴侣应用）」。
桥接端用独立的 F14 HID 快捷键替代普通右键，同一无障碍服务在首次按下时执行
`GLOBAL_ACTION_BACK`，消费按下、重复与松开事件，避免同时触发普通右键。
中键 Home 与右键 Back 独立配置并按设备保存，默认均为普通鼠标按钮；CLI 可用
`--right-button-action normal|back`。USB、Linux BLE、Windows BLE 共用该映射，macOS 支持 USB。
Windows 空闲 BLE provider 恢复会话时同步更新映射，不因修改该选项注销 GATT。

安装后打开手机 App，手动启用上述无障碍服务；已启用但更新后失效时可手动关闭再开启。
运行时无需 ADB 或通知使用权，未安装新版 APK、未启用服务或服务被 ROM 停止时不会执行 Back，
也不会回退发送普通右键。保留的 F13/F14 来自真实键盘时同样会被服务拦截，请避免用于其他快捷键。

`bridge_transport` 覆盖绝对/相对指针、Home 与 Back 同时按下、重复去重、切出/重置/关闭释放与恢复普通右键；
`android_accessibility` 用最小 Android API fake 执行真实服务，验证 Home/Back 分发、重复和松开不触发、
无关按键放行及全局操作失败仍消费快捷键；GUI 测试覆盖双语、设备隔离、保存恢复与参数传递。
均为离线测试，不代表手机 ROM 的 F14 映射、无障碍过滤或实际页面返回已经验收。

### Android 10–15 无反应修复（0.1.8）

F13/F14 的标准 Android KeyCode（326/327）到 API 36（Android 16）才加入。
在当前 Android 14 真机上，已确认 APK 0.1.7、无障碍服务已绑定、桥接进程带
`--right-button-action back`，且 AOA 键盘声明 F13/F14；但手机 Generic.kl 中
`key 183 F13` / `key 184 F14` 均为注释，不能依赖新系统 KeyCode 识别。

0.1.8（版本码10）保留新 KeyCode 路径，同时在事件为 `KEYCODE_UNKNOWN` 时，根据
Linux HID evdev 扫描码183/184识别 Home/Back。已映射为其他已知键的事件不作扫描码回退，
其他未知键仍放行；首次按下触发、重复/松开仅消费，失败不重试。USB/BLE 的桌面报告无需改变。

更新手机 APK 后打开一次，确认无障碍服务绑定；必要时由用户手动关闭再开启。
仅针对保留快捷键记录 `HID shortcut Back keyCode=0 scanCode=184 requested=true` 等日志，
不记录普通键盘输入。`requested=true` 表示系统接受全局操作请求，不等于已确认页面切换。
`android_accessibility` 现同时覆盖 Android 10–15 未映射事件和 Android16标准 KeyCode；
0.1.8 实际 ROM 事件投递及页面返回仍需安装后真机测试。
