# 分享至电脑与图片 / 文件传输

Android 伴侣应用 **0.1.6（版本码 7）** 与新版桌面 GUI 支持独立的双向文件通道。
原有 Deskflow + scrcpy **纯文本剪贴板同步不变**，本功能不自动读写任何一端剪贴板。
不安装 App、不开启 ADB，原有 USB AOA HID 键鼠仍可使用。

## 前提

- 同时更新桌面 GUI 和 APK，安装 APK 后先在手机打开一次。
- 使用已经在线、已授权的 USB ADB，或用户自行配对并连接的无线 ADB。
  桌面设备配置优先使用「ADB 目标」；仅 USB 模式可以回退该设备 USB 序列号。
  BLE 也可通过独立的显式 ADB 目标传文件，不使用 BLE MAC、不通过 HID 传文件。
- 不需要通知使用权、无障碍、所有文件访问权或存储权限，不开放局域网端口。
- Windows 若 ADB 与 WinUSB 驱动互斥，请使用已有的无线 ADB 连接；本功能不切换驱动。
- Linux、Windows、macOS 使用相同 Qt 实现，不依赖音频 / 剪贴板构建开关；CLI 暂不支持。

## 手机 → 电脑

1. 在相册、文件管理器、浏览器等应用中选择文本、图片或文件，通过系统分享菜单选择
   **「分享至电脑」**。支持单项及多选，也兼容 `ClipData` 中授予访问的内容 URI。
2. 在手机确认「准备分享」。App 读取此次明确分享的内容，在私有空间暂存，显示准备进度。
   分享的文本另存为 UTF-8 的 `shared-text.txt`；不会覆盖桌面的共享剪贴板。
3. 在桌面选中对应手机，点击连接按钮旁的 **「文件与分享」**，点击「刷新手机分享」。
4. 选择待接收文件（可多选），点击「接收所选文件」，再选择保存目录。
5. 文件通过 SHA-256 与长度校验后才在目标目录出现。名称前加传输 ID 的 8 位前缀以防重名，
   不覆盖同名文件、不自动打开。电脑保存成功后，才确认清除对应手机待发送记录。

分享本身不会自动向任意电脑推送，也不自动启动桌面服务。桌面窗口不会后台轮询；
再次分享后手动刷新。尚未接收的内容会保留在手机 App 的「文件与分享」中，可主动删除。
**任何已经获得该手机 ADB 授权的电脑**都属于此通道的信任范围，不另设网络配对码。

## 电脑 → 手机

1. 在桌面「文件与分享」中点击 **「发送文件到手机」**，选择一张 / 多张图片或其他文件。
2. 等待上传和手机校验完成。也可以把本地文件直接拖入桌面「文件与分享」窗口；拖拽只复制文件，
   不会删除电脑源文件。进度条统计当前文件的流式传输，在手机持久化回执确认前最多显示99%，
   整批完成后才显示100%。
3. 在手机打开伴侣 App → **「文件与分享」** → 刷新，查看已接收文件。
4. 默认文件先保存在 App 私有空间，点击文件下的 **「另存为」**，用 Android 系统文件选择器指定保存位置。
   也可以在手机「文件与分享」中开启自动保存：图片、视频和音频进入 MediaStore 媒体库，
   其他文件进入用户预先授权的 SAF 公共目录。上传先写私有临时文件，校验完成后才公开，
   不自动打开、不覆盖同名文件。
5. 另存完成后，可点击「删除私有副本」释放暂存空间；这不会删除另存到其他位置的文件。

手机系统选择器负责目的地及重名交互；App 不绕过选择器静默覆盖公共文件。
另存失败时原始私有副本保留，可以重试；文件提供方可能留下部分目标文件，请在选择器检查后处理。

## 限制与失败处理

- 每批最多 32 个文件，单文件上限 **1 GiB**；手机收件箱和待发送区合计最多 **32 个 / 2 GiB**。
  内容暂存为私有副本，需足够可用空间；低于预留空间时失败，清理不完整暂存。
- 图片按原始字节传输，不重新编码、不自动压缩；不提供缩略图、图片剪贴板、目录递归、
  后台自动接收或断点续传。桌面拖拽仅支持本地普通文件，不支持目录和非本地 URL。
  分享文本不等于复制粘贴，也不自动读取剪贴板。
- 单一窗口固定打开时的 ADB 目标，主窗口切换设备或编辑目标不会重定向在途操作。
  关闭该窗口后再为另一设备打开，避免发送错手机。键鼠会话可以保持连接。
- 可取消桌面传输或手机准备分享。取消只终止本功能创建的 ADB 子进程 / 流，
  不关闭 ADB server、不停止其他设备或 HID / 音频 / 剪贴板会话。
- 多文件逐个完成，不是整批原子事务。后续失败 / 取消时已经完成的文件保留；
  手机取消准备分享会尽力清理该次已暂存内容。进程被强杀后可能保留已完成项。
- 手机可能在取消前已经完成提交；这类文件仍出现在收件箱，不自动删除。检查后手动清理。
- 电脑接收失败会删除 `.deskflow-*.part` 临时文件，保留手机待发送副本，不确认接收。
  如果电脑已保存但手机清除失败，会单独提示；请勿重复接收，在手机删除对应待发送项。
  进程 / 主机崩溃可能留下电脑临时文件，需用户自行清理。
- 不自动 pair/connect、无目标回退、静默安装 / 启动 App、修改权限、执行收到的文件，
  也不记录文件正文或来源 URI。手机导出 provider 有可能唤起 App 进程处理文件请求，
  但不会主动打开 Activity 或启动通知监听服务。
- 断线、旧版 APK、存储耗尽、分享来源 URI 授权失效、ROM 禁止 provider 访问时直接失败；
  没有自动重试整个文件或回退其他目标。单命令握手 / 用户查询最多 5 秒，传输无进展最多30秒，
  每文件读写命令最多15分钟，手机持久化回执轮询有界。关闭 / 退出等待本功能子进程取消完成。

## 通道与安全边界

`TransferProvider` 的固定 authority 是 `com.github.gh6497.deskflowotg.transfer`。
manifest 读写权限均为 `android.permission.DUMP`，不授予 URI 权限；各方法另行检查调用 UID / 权限。
ADB shell 已有 DUMP，普通 App 不能读暂存、上传或伪造清除；分享入口本身公开，但必须由用户确认。
手机 App 不申请 DUMP。暂存文件使用不可控路径外的随机 32 位十六进制 ID，文件名仅作为元数据。
云备份和设备迁移明确排除 App 私有数据。

桌面每次操作先 `adb -s TARGET get-state`，再 `shell am get-current-user` 获取数字 Android 用户 ID。
`content` CLI 的 `--user` 必须是数字（不支持 `current`），后续请求固定该用户和目标。
远端命令只有固定词、数字用户 ID 和已验证随机 ID，**没有用户提供的文件名或路径**。

协议 v1：

- `exec-out content read --user USER --uri …/manifest`：至多64 KiB JSON，版本、ID、大小、SHA-256
  严格检查；`…/out/ID` 读取原始字节。电脑持久化后 `shell content delete …/out/ID`，
  再读 manifest 确认该 ID 消失；不能仅以 `content` 退出码或假定存在的成功文本判断。
- `shell -T base64 -d | content write …/in/ID`（管道在手机 shell 内执行）：桌面把完整协议流
  分块编码为 Base64，手机解码后交给 provider；Linux / Windows / macOS 共用此路径，APK 协议不变。
  只在末尾补 Base64 padding，保留最多2字节跨块余数；传输量约增加三分之一，不产生额外临时文件。
  shell v2 独立传递 stdin EOF 并等待远端命令完成。`-T` 仅禁用远端 PTY，Windows ADB 的
  本机 stdin 仍可能按文本模式处理（`0x1A` 截断、CRLF 改写），因此不能直接写二进制。
  不能使用 raw `exec-in`：它无法半关闭 stdin，
  可能在手机写入完成前结束通道，出现退出码0却无回执的上传失败。
  数据为8 字节 ASCII `DFOTGFT1`、大端 uint32 文件名 UTF-8 长度
  （1..1024）、文件名、大端 uint64 内容长度、内容、32 字节 SHA-256、EOF。
  手机逐块读入私有 `.ID.part`，校验长度 / 哈希 / 无尾随数据，写盘后原子改名为完成项。
  `…/receipt/ID` 返回已提交项；桌面核对 ID / 大小 / 哈希才报告完成。
  `content write` 即使拒绝上传也可能退出0；桌面检测其 provider 错误后直接报失败，不继续轮询回执。
- 一条桌面命令在途；文件以64 KiB分块，上传编码缓冲以256 KiB为水位（最多再加一个编码块），
  不把整个文件放入内存；进度和 SHA-256 仍按原始文件字节统计。
  手机仅允许一个桌面上传在途，分享源也在工作线程读取。异常 / 截断 / 校验失败不产生回执。

## 验证

```bash
python3 tests/test_android_transfer.py
ctest --test-dir BUILD_DIR --output-on-failure -R 'companion_transfer|android_transfer|gui_window|gui_logic'
cd android/deskflow-otg
ANDROID_HOME=/path/to/Android/Sdk ./gradlew :app:assembleDebug :app:lintDebug
```

主机 Java 测试运行真实的流协议和私有存储核心，覆盖二进制 / 空文件、哈希、截断、尾随数据、
版本 / 大小限制、文件名、取消、失败清理、队列上限、持久化和重启清理。
Qt 使用跨平台 fake ADB 验证双向二进制、数字用户 / 精确目标、无自动接收、无远端路径注入、
同名保护、确认清理、错误回执、断线、超时、取消、背压与窗口生命周期；模拟 Windows ADB
文本 stdin 的 Ctrl-Z EOF / CRLF 转换，验证空文件、跨64 KiB和 Base64三字节边界及大文件。
测试不访问手机、系统蓝牙或真实 ADB server，**不等同真实 ROM 的分享菜单、URI 授权、
provider 权限 / 后台投递或 Windows/macOS 真机验收**。

2026-11-05 Linux + USB ADB 真机排障：同一有效小文件经 `exec-in` 退出0但没有提交回执，
改用 `shell -T` 后提交成功。修复后的真实 `CompanionTransfer` 另通过1,280,000字节二进制
文件（含全部字节值）及空文件上传，手机回执的长度和SHA-256核对通过；仅清理此次诊断项。
这不等同手机分享菜单、SAF另存为或Windows/macOS真机验收，仍需分别验证。

2026-11-10 Windows + 无线 ADB（37.0.1）/ Redmi K20 Pro / 伴侣0.1.12真机排障：
`shell -T wc -c` 对含全部字节值的1 MiB输入仅收到26字节（首个`0x1A`处EOF），
CRLF也被转换；Base64解码链路的同一数据SHA-256正确。原始桌面实现的新文本stdin模拟
回归先失败，分块编码修复后通过。实际 `CompanionTransfer` 上传空文件、1 MiB和
16 MiB + 1字节均收到成功回执，并另行核对手机公共目录文件的SHA-256；仅清理诊断项。
测试中该ROM在锁屏后冻结伴侣线程（`do_freezer_trap`），大文件因此超时；保持伴侣前台亮屏
后完成验证。传输期间应保持伴侣运行，以上不代表此ROM锁屏后台传输已通过，也不代表macOS真机验收。
